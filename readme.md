# Простой веб-сервер на встроенном Python

Минималистичный локальный веб-сервер, написанный на стандартной библиотеке Python (`http.server`). Сервер автоматически отдает главную HTML-страницу, корректно связывает статические файлы (CSS/JS) и имеет встроенную систему обработки ошибок с выводом кастомных страниц.

## 📂 Структура проекта

Для работы сервера структура файлов в вашей папке должна выглядеть следующим образом:

```text
название_проекта/
│
├── static/                # Папка для статических файлов
│   ├── css/
│   │   └── style.css      # Ваши стили
│   └── js/
│       └── script.js      # Ваши скрипты
│
├── web/                   # Папка для шаблонов страниц
│   ├── index.html         # Главная страница (Bootstrap-верстка)
│   ├── 404.html           # Кастомная страница ошибки 404
│   └── 500.html           # Кастомная страница ошибки 500
│
├── server.py              # Код сервера
└── .gitignore             # Исключения для Git
```

## 🚀 Как запустить проект

1. Убедитесь, что у вас установлен Python 3.
2. Откройте терминал в корневой папке проекта и запустите команду:
   ```bash
   python server.py
   ```
3. Откройте браузер и перейдите по адресу: [http://localhost:8000](http://localhost:8000)

## 🛠️ Как подключать CSS и JS в HTML-шаблонах

Поскольку сервер обрабатывает статику через проверку пути `/static/`, пути к стилям и скриптам во всех шаблонах (включая страницы ошибок) должны начинаться со **слеша `/`**:

```html
<!-- Кастомные стили из папки static -->
<link rel="stylesheet" href="/static/css/style.css">

<!-- Кастомный скрипт -->
<script src="/static/js/script.js"></script>
```

## 📝 Дополнительный функционал и обработка ошибок

В сервере реализована отказоустойчивая обработка запросов и кастомная маршрутизация для нештатных ситуаций:

* **Ошибка 404 (Not Found)**: 
  * Срабатывает, если запрашиваемый статический файл в папке `/static/` не существует на диске.
  * Вместо стандартного белого экрана браузера сервер возвращает оформленную страницу `web/404.html`.
  * Если сам файл `404.html` отсутствует, сервер отдаст резервную текстовую строку.

* **Ошибка 500 (Internal Server Error)**:
  * Вся логика обработки запросов обернута в блок `try-except`. Если внутри кода произойдет непредвиденный сбой (например, конфликт прав доступа при чтении файла), сервер не «упадет».
  * Пользователь получит корректный HTTP-статус `500` и увидит сверстанную страницу `web/500.html`.

* **Защита и MIME-типы**: Сервер автоматически проставляет `Content-type` (`text/css` или `application/javascript`), благодаря чему современные браузеры без блокировок применяют стили и выполняют скрипты.
